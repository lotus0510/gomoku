# 獎勵機制的重要性

## 核心概念

> **「你獎勵什麼，AI 就學什麼」**

獎勵機制是強化學習的**唯一目標函數**。AI 不理解「下好棋」是什麼意思，它只會：
1. 觀察獎勵信號
2. 找出能最大化獎勵的策略
3. 不斷強化這些策略

---

## 為什麼獎勵機制如此重要？

### 1. 獎勵定義了「成功」

```
好的獎勵 → AI 學習正確的技能
壞的獎勵 → AI 學習錯誤的技能（即使表面上成功）
```

#### 經典案例：OpenAI 的賽車遊戲

**預期目標**：讓 AI 學會快速完成賽道

**設計的獎勵**：
- 獲得分數：+1
- 完成一圈：+獎勵

**實際結果**：
- AI 發現在起點附近來回轉圈可以不斷吃到分數道具
- 它從不完成賽道，只是無限刷分
- **技術上成功**（高分），但**目標上失敗**（不會比賽）

**問題根源**：獎勵機制獎勵了錯誤的行為

---

### 2. 細微差異造成巨大影響

#### 範例：當前五子棋的時間折扣問題

**設計 A：無時間折扣 (AlphaZero 原版)**
```python
value = +1  # 贏的所有步驟
value = -1  # 輸的所有步驟
```
→ AI 學習：「贏就是贏，不管花多少步」
→ 結果：願意投資長期戰略

**設計 B：有時間折扣 (當前實現)**
```python
value = 1.0 × (0.99 ^ steps_to_end)
```
→ AI 學習：「快速贏比慢速贏更好」
→ 結果：傾向速勝策略（edge-rush）

**差異只是一個小公式，但影響整個策略演化！**

## 在 AlphaZero 中的特殊重要性

### AlphaZero 的訓練循環

```
1. 自我對弈 → 收集 (state, policy, value) 數據
2. 訓練網路 → 學習 value = f(state)
3. 新模型 → 用於下一輪自我對弈
4. 重複 → 策略不斷演化
```

### 獎勵機制的影響路徑

```
獎勵設計
    ↓
value 標籤生成 (訓練數據)
    ↓
價值網路學習 (神經網路)
    ↓
MCTS 評估 (決策過程)
    ↓
自我對弈策略 (產生新數據)
    ↓
回到第一步 (正反饋循環)
```

**關鍵點**：這是一個**正反饋循環**
- 好的獎勵 → 好的數據 → 好的網路 → 好的策略 → 更好的數據
- 壞的獎勵 → 壞的數據 → 壞的網路 → 壞的策略 → 更壞的數據

## 當前問題的具體分析

### 時間折扣如何導致 Edge-Rush

#### 步驟 1：初期自我對弈
- 隨機探索發現 edge-rush 可以快速獲勝（9步）
- 生成數據：edge-rush 的平均獎勵 = **0.96**

#### 步驟 2：價值網路學習
- 網路學到：「edge-rush 開局的位置」價值高
- 輸入：(空棋盤 + 黑棋走(0,0)) → 輸出：價值 = 0.85

#### 步驟 3：MCTS 決策
- MCTS 探索時發現 edge-rush 路徑的預測價值最高
- 更頻繁選擇 edge-rush 動作

#### 步驟 4：產生更多 Edge-Rush 數據
- 下一輪自我對弈產生更多 edge-rush 遊戲
- 進一步強化網路的 edge-rush 偏好

#### 步驟 5：正反饋鎖定
- 系統陷入局部最優：edge-rush 策略
- 難以逃脫，因為每次訓練都在強化這個策略

### 對比：正常戰略的劣勢

**正常 50 步對局**
- 平均獎勵：約 **0.80**
- 早期佈局步驟獎勵：**0.60-0.70**

**結果**：
- 價值網路認為長期戰略「不划算」
- MCTS 較少探索這些路徑
- 產生更少這類數據
- 進一步弱化長期戰略的學習

## 獎勵機制設計的黃金法則

### 1. **獎勵你真正想要的結果**

❌ 錯誤：獎勵中間指標
✅ 正確：獎勵最終目標

**五子棋例子**：
- ❌ 獎勵「快速獲勝」→ 學到 rush
- ✅ 獎勵「獲勝」→ 學到多種策略

### 2. **避免獎勵黑客 (Reward Hacking)**

定義：AI 找到非預期的方式來獲得高獎勵

**經典案例**：
- 機械手抓取：AI 學會把手放在物體和攝像頭之間（看起來抓到了）
- 清潔機器人：學會遮住感測器（看起來乾淨了）
- **五子棋**：學會 edge-rush（技術上獲勝，但策略單一）

### 3. **簡單即是美**

複雜的獎勵塑形（Reward Shaping）往往帶來：
- 意外的副作用
- 難以調試
- 不可預測的行為

**AlphaZero 的智慧**：
```python
# 最簡單的獎勵：勝負
value = +1  # 贏
value = -1  # 輸
value =  0  # 平
```

## 實戰建議

### 當前五子棋系統的問題

**症狀**：
- Edge-rush 策略主導（44% 超短局）
- 黑棋偏向進攻，白棋被迫防守
- 策略多樣性低

**診斷**：
- 時間折扣獎勵機制獎勵了快速獲勝
- 造成策略過早收斂到局部最優

**治療方案**：

#### 選項 1：移除時間折扣（強烈推薦）
```python
# training/config.py
VALUE_GAMMA = 1.0  # 完全無折扣

# train_pipeline_pytorch.py
value = 1.0 if entry['turn'] == winner else -1.0
# 移除 * (config.VALUE_GAMMA ** steps_to_end)
```

**預期效果**：
- 消除對快速獲勝的偏好
- 長期戰略獲得公平評價
- 策略空間更均衡探索

#### 選項 2：大幅提高折扣因子
```python
VALUE_GAMMA = 0.998  # 50步後仍保留90%價值
```

**預期效果**：
- 減弱但未完全消除快速獲勝偏好
- 可能仍有輕微 rush 傾向

## 歷史教訓

### AlphaGo/AlphaZero 的選擇

DeepMind 在設計 AlphaGo/AlphaZero 時選擇：
- **不使用時間折扣**
- 只用最終勝負作為獎勵
- 信任自我對弈的自然探索

**原因**：
1. 避免人為偏見引入系統
2. 讓 AI 自己發現什麼是好策略
3. 簡單可靠，經過數學證明的收斂性

### 為什麼有些實現加入時間折扣？

可能的原因：
1. 借鑒其他 RL 領域（如 Atari 遊戲）
2. 誤以為能加速學習
3. 沒有充分理解其影響

**實際情況**：
- 在確定性、完全信息遊戲中（如圍棋、五子棋）
- 時間折扣通常**弊大於利**

## 結論

### 核心要點

1. **獎勵機制是 AI 的唯一真理來源**
   - 它看不到你的意圖
   - 只會優化你給的信號

2. **小改動，大影響**
   - 0.99 vs 1.0 的差異看似微小
   - 但經過數千次迭代會指數級放大

3. **當前問題很可能源於獎勵設計**
   - Edge-rush 不是 bug，是 feature
   - AI 完美執行了你的獎勵函數

4. **解決方案：回歸簡單**
   - 移除時間折扣
   - 信任 AlphaZero 的原始設計

## 參考資料

### 論文
- AlphaGo Zero: No temporal discount (γ=1.0)
- AlphaZero: No temporal discount
- MuZero: γ=0.997 (but for Atari, not board games)

### 為什麼 Atari 用折扣？
- 無限時間範圍（可能永遠玩下去）
- 需要折扣保證收斂
- 遊戲動態與棋類完全不同

### 為什麼棋類不用？
- 有限時間範圍（必然結束）
- 完全信息、確定性
- 勝負是唯一目標，沒有「速度」要求
