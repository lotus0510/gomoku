# 訓練改進方案

## 🎯 目標

1. **調整學習率調度** - 更頻繁、更溫和的衰減
2. **增加探索性** - 防止過早收斂到局部最優
3. **穩定訓練** - 避免策略崩潰和振盪

---

## 🔍 問題根源分析

### 當前訓練的核心問題

#### 1. **探索不足 → 過早收斂**

**現象**：
- 白棋學到單一策略（Edge-Rush）
- Top-1 機率 = 1.0（100% 確定）
- 所有 10 步遊戲都是相同模式

**根本原因**：
```
MCTS 探索階段太短 → 快速找到簡單策略 → 停止探索其他可能性
     ↓
自我對弈強化錯誤策略 → 模型過度自信 → 更不願意探索
     ↓
陷入局部最優（Edge-Rush）→ 無法學到更複雜的策略
```

**證據**：
- Dirichlet epsilon = 0.25（較低）
- 溫度閾值 = 25 步（前 25 步探索，之後就確定性選擇）
- 白棋每步都 100% 確定選擇第 0 行

#### 2. **學習率過高且不衰減 → 過擬合**

**現象**：
- 學習率固定 0.0001（38 次迭代未衰減）
- 訓練劇烈振盪（迭代 28-29 健康，30-34 崩潰）
- 策略在黑白優勢間來回翻轉

**根本原因**：
```
學習率 0.0001 過高 → 梯度更新幅度大 → 過度修正策略
     ↓
某次迭代學到白棋 Rush → 下次迭代過度強化 → 黑棋策略崩潰
     ↓
數據分佈劇變（90% 白棋勝）→ 再次大幅更新 → 策略再次翻轉
```

**證據**：
- 勝率標準差 = 0.172（高振盪）
- 翻轉次數 = 3（10 次迭代中）
- 學習率 400 次迭代才衰減一次

#### 3. **價值網路失去判別力 → 指導失效**

**現象**：
- 所有 values = 0.0
- 價值標準差接近 0
- MCTS 無法靠價值網路指導搜索

**根本原因**：
```
訓練數據極度偏斜（白棋 90% 勝）→ 價值網路學到「都是 0」最安全
     ↓
Loss 函數懲罰預測偏差 → 預測中間值（0）最小化損失
     ↓
價值網路輸出趨向 0 → 失去判別能力 → MCTS 退化為隨機搜索
```

**證據**：
- values 陣列全 0.0（100%）
- value_std 從 0.8 下降到 0.5
- 價值 MAE 維持在 0.98（接近 1，說明預測和真實差距大）

## 💊 解決方案設計

### 方案 A：漸進式改進（推薦）

**理念**：小步快跑，逐步調整，避免過度干預

#### 改進 1：學習率調度優化

```python
# training/config.py

# === 原配置 ===
LEARNING_RATE = 0.0001
LR_DECAY_STEPS = 400      # 每 400 次迭代衰減
LR_DECAY_RATE = 0.7       # 衰減至 70%

# === 新配置 ===
LEARNING_RATE = 0.0001    # 保持初始學習率
LR_DECAY_STEPS = 100      # 改為每 100 次迭代衰減（4倍頻率）
LR_DECAY_RATE = 0.8       # 改為衰減至 80%（更溫和）
MIN_LEARNING_RATE = 1e-5  # 保持最小值
```

**學習率時間表對比**：

| 迭代 | 原配置 | 新配置 | 改善 |
|------|--------|--------|------|
| 0-99 | 0.0001 | 0.0001 | 相同 |
| 100-199 | 0.0001 | 0.00008 | ✓ 開始衰減 |
| 200-299 | 0.0001 | 0.000064 | ✓ 持續衰減 |
| 300-399 | 0.0001 | 0.000051 | ✓ 更穩定 |
| 400-499 | 0.00007 | 0.000041 | ✓ 平滑過渡 |
| 500-599 | 0.00007 | 0.000033 | ✓ 細粒度調整 |

**優勢**：
- ✅ 前 100 次迭代穩定探索（學習率不變）
- ✅ 之後逐步降低，防止過擬合
- ✅ 衰減更溫和（0.8 vs 0.7），避免突變
- ✅ 到迭代 1000 時，學習率約為 1.3e-5（接近下限）

#### 改進 2：探索性增強

```python
# training/config.py

# === MCTS 探索參數 ===
# 原配置
DIRICHLET_EPSILON = 0.25    # Dirichlet 噪聲權重
DIRICHLET_ALPHA = 0.3       # Dirichlet 分佈參數
C_PUCT = 1.5                # PUCT 探索常數

# 新配置
DIRICHLET_EPSILON = 0.35    # 提高至 0.35（增加 40% 探索）
DIRICHLET_ALPHA = 0.3       # 保持不變
C_PUCT = 2.0                # 提高至 2.0（更傾向探索未訪問節點）

# === 溫度探索參數 ===
# 原配置
TEMP_THRESHOLD_MOVE = 25    # 前 25 步使用溫度 1.0
TEMP_FINAL_MOVE = 50        # 25-50 步使用溫度 0.5

# 新配置
TEMP_THRESHOLD_MOVE = 30    # 延長至 30 步（增加 20%）
TEMP_FINAL_MOVE = 60        # 延長至 60 步（增加 20%）
```

**改進效果**：

**Dirichlet 噪聲增強**：
```python
# 噪聲混合公式
policy_with_noise = (1 - epsilon) * policy + epsilon * noise

# 原配置（epsilon=0.25）
# 策略 75% 來自網路，25% 來自隨機噪聲

# 新配置（epsilon=0.35）
# 策略 65% 來自網路，35% 來自隨機噪聲
# → 強制探索更多可能性
```

**溫度探索延長**：
```
原配置：
  步驟 1-25:  溫度 1.0（完全隨機選擇）
  步驟 26-50: 溫度 0.5（部分隨機）
  步驟 51+:   溫度 0.01（幾乎確定性）

新配置：
  步驟 1-30:  溫度 1.0（多探索 5 步）
  步驟 31-60: 溫度 0.5（多探索 10 步）
  步驟 61+:   溫度 0.01
```

**C_PUCT 增強**：
```
PUCT 公式：PUCT = Q(s,a) + C_PUCT * P(s,a) * sqrt(N(s)) / (1 + N(s,a))

C_PUCT 越大 → 越傾向選擇：
  - 訪問次數少的動作（N(s,a) 小）
  - 先驗機率高的動作（P(s,a) 大）

1.5 → 2.0：增加 33% 探索傾向
```

## 🔬 理論依據

### 為什麼增加探索性？

**AlphaZero 論文**：
> "足夠的探索對於發現新策略至關重要。Dirichlet 噪聲確保了即使在自我對弈中也能探索多樣化的開局。"

**我們的情況**：
- 探索不足 → 快速收斂到簡單策略（Edge-Rush）
- 增加噪聲 → 強制嘗試不同開局 → 發現更好策略

### 為什麼調整學習率？

**深度學習經驗**：
> "學習率調度是訓練穩定性的關鍵。固定學習率容易在後期過擬合。"

**我們的情況**：
- 固定 lr → 後期仍大幅更新 → 策略振盪
- 逐步衰減 → 前期快速學習 + 後期精細調整 → 穩定收斂

### 為什麼不一次改變太多？

**科學實驗原則**：
> "單變量實驗：一次只改變一個變量，才能確定因果關係。"

**方案 A vs 方案 B**：
- 方案 A：小幅調整 → 容易定位問題 → 可逐步優化
- 方案 B：大幅調整 → 如果失敗難以定位原因 → 風險高

## ⚠️ 風險與對策

### 風險 1：過度探索導致訓練緩慢

**表現**：
- 遊戲長度過長（>80 步）
- 策略不收斂
- 勝率長期接近 50%（無進步）

**對策**：
- 監控迭代 50-100
- 如果平均長度 >60 步且無改善 → 降低 epsilon 到 0.30
- 如果 Top-1 持續 <0.15 → 降低 C_PUCT 到 1.8

### 風險 2：學習率衰減過快

**表現**：
- 梯度範數急劇下降（<0.2）
- 損失停止下降
- 策略停止改進

**對策**：
- 監控梯度範數
- 如果 <0.2 持續 10 次 → 提高學習率（× 1.5）
- 或延長衰減步長（100 → 150）

### 風險 3：仍然出現振盪

**表現**：
- 勝率在黑白優勢間跳動
- 策略質量不穩定

**對策**：
- 進一步降低學習率（0.00005）
- 增加數據增強（8 倍 → 16 倍）
- 考慮使用經驗回放的優先級權重
